## Design Context

### Users

Hardware builders, students, and embedded developers use Schematic while composing a real circuit with an AI agent. They need to move quickly between visual wiring, firmware, simulation, diagnostics, and sourcing parts without losing the project state.

### Brand Personality

Trustworthy, technical, and focused. The interface should create confidence that each action is visible, explainable, and connected to a real project graph.

### Aesthetic Direction

A refined industrial workbench: dense enough for engineering workflows, quiet enough for long coding sessions, and precise rather than decorative. Support both dark and light themes, with restrained accents and clear state colors. Avoid generic AI-dashboard styling, excessive cards, ornamental gradients, and visual noise.

### Design Principles

1. Make system state legible: running, saved, invalid, unavailable, and complete should never be ambiguous.
2. Keep the canvas, code, diagnostics, and procurement views connected through consistent terminology and feedback.
3. Prefer compact, high-signal controls with generous keyboard and touch affordances.
4. Use hierarchy and spacing to reduce cognitive load instead of adding decoration.
5. Treat failure states as first-class product surfaces with a clear recovery path.

### Quality Bar

Flagship product quality: polished, reliable, and calm under complex hardware workflows.
